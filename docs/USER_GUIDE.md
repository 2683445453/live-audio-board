# LiveAudioBoard 使用指南

本文对应 LiveAudioBoard `0.22.x`，覆盖安装、资料库、直播路由、录音、编辑、下载和故障恢复。

## 1. 安装与首次启动

推荐从 [GitHub Releases](https://github.com/2683445453/live-audio-board/releases/latest) 下载
`LiveAudioBoard-win-Setup.exe`。Setup 按当前 Windows 用户安装并支持应用内更新；MSI 适合
标准部署；便携 ZIP 解压后可直接运行。

正式发行包为 `win-x64` 自包含应用，不要求用户安装 .NET。未签名版本可能出现 SmartScreen
提示，可使用 Release 页面中的 `SHA256SUMS.txt` 校验文件。

首次启动会在 `%LOCALAPPDATA%\LiveAudioBoard.UserData` 创建资料库和设置。该目录与更新器
管理的安装目录分离，卸载或更新程序不会主动删除其中的音频、数据库和备份。0.22.3 或更高
版本首次启动时会安全复制旧目录中的现有数据，复制失败时仍保留旧副本并停止切换。
高级恢复时也可在命令行运行 `LiveAudioBoard.exe --migrate-user-data`，只执行迁移而不打开界面。

## 2. 导入和整理音频

- “导入音频”可选择一个或多个受支持文件；
- “导入文件夹”会递归扫描目录，并按首级子目录自动建立分类；
- 文件或文件夹可以直接拖入主窗口；
- 音效卡可拖动调整顺序，也可拖入左侧分类；
- 左侧“分类”旁的“＋”可以创建并持久保存空分类；
- 打开音效卡的“音频设置”，可选择已有分类或输入自定义分类并保存；
- 搜索、分类和收藏筛选会共同作用于每页 8 条的音效宫格。

新文件会复制到内容寻址的 `Media` 目录，并计算 SHA-256。完全相同的内容只保存一份。
旧版本记录的外部路径不会在启动时被强制移动。

## 3. 播放和快捷键

每条音效支持：

- 音量、淡入、淡出和播放进度；
- 单曲循环和独占播放；
- 波形图起止裁切：拖动左右手柄调整边界，拖动高亮选区整体平移；
- 0–5000 ms 播放冷却，避免连按造成重复叠音；
- 独立全局快捷键和冲突检测；
- 全部音效快捷键总开关、单条绑定启停，以及“保留前台软件原按键功能”选项；
- “直播 + 监听”“仅直播”“仅监听”三种路由。

循环音效再次点击播放按钮或触发同一快捷键即可停止。`Ctrl+Shift+F10` 是全局紧急停止，
始终立即结束全部播放。

## 4. 直播输出与主播监听

软件提供两条独立 WASAPI 总线：

- **直播输出**：送往 OBS 或虚拟声卡；
- **主播监听**：送往耳机或监听音箱。

若两个总线选择同一设备，“直播 + 监听”只播放一次，避免音量翻倍。需要严格隔离时：

1. 安装并配置 VB-CABLE、VoiceMeeter 等虚拟设备；
2. 将 LiveAudioBoard 的直播输出设为虚拟设备；
3. 将主播监听设为耳机；
4. 在 OBS 中捕获虚拟设备。

OBS 的“应用程序音频捕获”可能同时捕获本进程的监听总线，不适合需要严格隔离的场景。
输出设备热插拔、Windows 默认设备切换和设备失效会触发自动刷新与安全回退。

## 5. 响度和峰值安全

离线分析会计算 EBU R128 风格的整合响度、样本峰值和建议增益。建议目标为 `-16 LUFS`，
并保留 `-1 dBFS` 峰值余量。建议增益需要由用户主动启用。

单曲软峰值保护在进入混音器前约束峰值；全部声音叠加后还会经过最终 `-1 dBFS` 主总线
限幅器。底部电平区显示实时峰值和增益衰减；出现“总线限幅”时，应减少同时播放数量或
降低单曲音量。

“批量分析响度”只处理尚无完整数据的音频，每完成一条立即保存。损坏或缺失文件会被隔离，
不会中断整个队列。

## 6. 录音和另存新音效

录音支持默认麦克风和 Windows 系统回环，最长时长可设为 15–300 秒。录制时显示输入电平，
结束后可自动裁剪首尾静音，并统一转换为 48 kHz 双声道 WAV 后入库。

音频设置中的“另存新音效”会将波形选区、音量、淡入淡出、建议增益和峰值保护渲染为新文件。
可输出 48 kHz WAV、192 kbps MP3 或 192 kbps M4A/AAC，原文件保持不变。新文件从中性播放
设置开始，避免重复应用已经烘焙的增益和淡化。

## 7. 下载中心

### 开放音频搜索

Openverse 提供 Freesound、Jamendo 和 Wikimedia Commons 聚合结果。Internet Archive 适配器
只显示明确标注 CC0、公共领域或 CC BY，且能够找到可处理音频文件的馆藏；BY-SA、BY-NC、
BY-ND 和无明确许可证条目会被排除。

搜索结果可以先在主播监听设备试听。下载会进入后台队列，最多同时进行 3 项；关闭下载中心
不会停止队列。每项可单独取消，已结束记录可清理，重复活动地址不会被再次加入。

### Freesound 原始文件

1. 在“Freesound 授权”中打开 API 凭据申请页面；
2. 创建应用并使用 Freesound 提供的托管授权码页面作为 Redirect URL；
3. 填写 Client ID 和 Client Secret，打开授权页面；
4. 复制一次性授权码回软件完成连接。

凭据保存在 `%LOCALAPPDATA%\LiveAudioBoard.UserData\freesound.auth`，使用 Windows 当前用户 DPAPI
加密。Access Token 过期后会自动尝试刷新。不得提交或分享该文件。

### RSS/Atom 与直链

RSS 2.0、Media RSS 和 Atom 模式会读取公开 Feed 中的音频附件。直链模式只处理合法、可直接
访问的 HTTP/HTTPS 音频文件，不解析网页、绕过登录或 DRM，也不抓取流媒体平台。

支持 ETag 或 Last-Modified 的服务器会保留按 URL 隔离的 `.part` 状态。网络中断后重新下载
同一地址即可使用 HTTP Range 续传；如果服务器忽略 Range 或内容标识变化，会安全地从头下载。

### 内容许可责任

音频搜索结果和 Feed 仅帮助发现内容，不代表自动获得使用权。下载前应打开来源页面，核对
作者、许可证、署名、演绎和商业使用条件。LiveAudioBoard 的软件许可证与音频内容许可证
相互独立。

## 8. 备份、找回和日志

SQLite 数据库每 24 小时自动备份一次，默认保留最近 10 份。启动时会检查资料库文件：

- 如果原路径失效但 `Media` 中存在同哈希托管副本，会自动恢复；
- 已有 SHA-256 的记录只接受内容完全相同的重新定位文件；
- 旧记录没有哈希时允许建立新托管副本，但会重置旧响度和裁剪数据。

异常会写入 `%LOCALAPPDATA%\LiveAudioBoard.UserData\Logs`，默认保留最近 20 份。日志包含异常堆栈、
应用、系统和运行时版本，不会自动上传。
